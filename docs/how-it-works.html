gnss-imu-fusion

How it works

From NMEA text and Xbus bytes to typed measurements in metres, and the Kalman core both filters share.

getting startedhow it worksreadme

Both projects start from the same raw bytes: NMEA text from a u-blox MAX-M10S at 9600 baud, and binary Xbus packets from an Xsens MTi-630 at 115200 baud. This repo turns those bytes into typed, timestamped measurements and provides the linear-algebra and filter core that each project builds its estimator on.

gps: nmea sentences

The receiver prints one line per sentence, ending in *hh, an XOR checksum of every character between $ and *. Lines that fail the checksum are dropped. Two sentences are used:

$GNRMC,072223.00,A,3958.59211,N,03244.28744,E,0.012,,191024,,,A*6C
       time      ok lat         lon         knots course date
$GNGGA,072223.00,3958.59211,N,03244.28744,E,1,05,2.30,894.2,M,...
       time                                  sats hdop altitude
  • Coordinates are ddmm.mmmm (latitude) and dddmm.mmmm (longitude), so degrees = dd + mm.mmmm/60, negated for S and W. time_and_location validates every field. A malformed one throws instead of yielding a silently wrong position.
  • RMC gives the position, speed over ground (knots → m/s) and true course. Status V means no fix.
  • GGA gives the altitude and the HDOP, which sets how far each fix is trusted (σ ≈ HDOP × UERE).
  • Epoch pairing. Receivers send the GGA right after the RMC of the same second. gps::process_sentence holds a valid RMC until the GGA with the same timestamp arrives and returns one gps_fix with both. Without the pairing, a climbing vehicle would get last second's altitude.

utm: degrees to metres

A filter wants a flat Cartesian frame. UTM splits the earth into 60 six-degree zones and projects each with a transverse Mercator. Within a zone, easting and northing are metres with a small, known scale error. utm implements the forward and inverse series (the NGS/USGS formulas in docs/) and the grid convergence: the angle between grid north and true north. Course and IMU headings are relative to true north, so the filters rotate them by the convergence before mixing them with UTM positions.

imu: xbus packets

FA  FF  36  len  [ data … ]  checksum
preamble bus mid      mtdata2 items   sum of bytes after FA ≡ 0 (mod 256)
  • Framing (xbus_packet) is a byte-by-byte state machine. If a checksum fails, it rescans the buffered bytes from the next FA, so a real packet hidden inside a corrupted one is not lost.
  • MTData2 is a list of [data id (2 B), size (1 B), payload] items, big-endian floats. The parser reads the sample time (10 kHz ticks), quaternion, acceleration, free acceleration, rate of turn, Euler angles and status. The low bits of the data id give the output frame (ENU, NED, NWU).
  • Acceleration in ENU. Xbus::accelerationENU() prefers the device's free acceleration (gravity already removed). Otherwise it rotates the raw specific force by the orientation quaternion into the local frame and subtracts g. At rest an accelerometer reads +g upward, which is why the subtraction is needed. Any error in g becomes a constant vertical bias, so the value is a parameter.

the filter core

matrix<R, C> is a fixed-size, stack-allocated matrix with sizes checked at compile time, and inverse() is Gauss–Jordan with partial pivoting. kalman_filter<N> is the generic linear Kalman filter both projects use:

predict: x ← F x + u P ← F P Fᵀ + Q innovate: y = z − H x S = H P Hᵀ + R gate: NIS = yᵀ S⁻¹ y (χ² with dim z dof; reject above the 99.9 % value) update: K = P Hᵀ S⁻¹ x ← x + K y P ← (I − K H) P (I − K H)ᵀ + K R Kᵀ

The last line is the Joseph form. It costs a little more than (I − K H) P but keeps P symmetric and positive definite despite rounding. A filter that runs at 100 Hz for hours needs that.

threads and events

Each serial port has a reader thread. Readers push a sensor_event (gps_fix, an Xbus sample, or end_of_stream) into one thread-safe queue. A single consumer pops events in arrival order and owns the filter, so the filter needs no locks.

simulation helpers

  • local_frame.hpp: WGS84 lat/lon/height ⇄ the local ENU tangent plane that a Gazebo world with <spherical_coordinates> uses, to compare an estimate with Gazebo's ground truth.
  • error_stats.hpp: running mean, RMS, max and percentiles of an error. p95 is the error that 95 % of samples stay under: it shows the bad cases without being set by one outlier.
  • AccuracyOverlay: a Gazebo GUI plugin that subscribes to /positioning/overlay and draws the live accuracy text over the 3D view. sim/gui.config is the window layout both simulations start with.
