localization_core

Getting started

Build the shared library, use it from a project, and keep the three repositories in step.

getting startedhow it worksreadme

This repository is the common base of two projects. It holds the sensor parsers, coordinate conversion, IMU driver, matrix and Kalman filter core, and the Gazebo helpers that both projects use. The projects pull it in as a git submodule.

localization_core

this repo: nmea, utm, xbus/mti-630, serial port, gps reader, matrix, kalman_filter, sim helpers, gazebo overlay

gnss_imu_prediction

gps + imu kalman filter, predicts the position 1 s ahead; device program and the “ghost” simulation

drone_localization

locates a drone in 3d from external sensors (currently a pole with uwb range and a yolo camera bearing)

1. get all three side by side

The projects find this repo through the relative submodule URL ../localization_core, so keep the three clones in the same parent directory, both locally and on GitHub (same account).

cd ~
git clone <url>/localization_core
git clone --recurse-submodules <url>/gnss_imu_prediction
git clone --recurse-submodules <url>/drone_localization
For clones that live only on your disk, git refuses local (file://) submodules by default. Inside a project run
git -c protocol.file.allow=always submodule update --init

2. build and test this repo

  1. Prerequisites. CMake ≥ 3.22 and a C++20 compiler (GCC 13+ or Clang 16+). Boost (Asio, header only) is optional: without it the serial port, gps and mti_630 libraries are skipped and everything else still builds. 
    sudo dnf install cmake gcc-c++ boost-devel     # fedora
sudo apt install cmake g++ libboost-dev        # ubuntu
  2. Configure and build. 
    cmake -S . -B build
cmake --build build -j
  3. Run the tests. 
    ctest --test-dir build --output-on-failure
# or directly, to see every case:
./build/test/cpp/tests

    Expect [ OK ] for the nmea, rmc, utm, xbus and matrix tests, plus gps_altitude_pairing when Boost was found.

  4. Optional: the Gazebo overlay plugin. When Gazebo Harmonic (gz-gui8, gz-transport13, gz-msgs10) and Qt5 are found, AccuracyOverlay is built into build/gz_gui_plugins/. The projects' run scripts point GZ_GUI_PLUGIN_PATH there for you.

3. use it from a project

git submodule add ../localization_core external/localization_core
cmake_minimum_required(VERSION 3.22)
project(my_project LANGUAGES CXX)

include(external/localization_core/cmake/common.cmake)   # c++20 + warnings
add_subdirectory(external/localization_core)

add_executable(my_tool tool.cpp)
target_link_libraries(my_tool PRIVATE utm xbus localization_core_headers)

if(TARGET gps AND TARGET mti_630)    # only with boost
  target_link_libraries(my_device PRIVATE gps mti_630 Threads::Threads)
endif()
targetgives youneeds
time_and_locationutc / date / coordinate parsers
rmcchecksum-verified $..RMC sentence
utmlat/lon ⇄ utm, grid convergence
xbusxbus framing, mtdata2 → Xbus sample, acceleration in ENU
localization_core_headersmatrix, kalman_filter<N>, gps_fix, sensor_event, queue
serial_port, gps, mti_630live readers for the max-m10s and the mti-630boost
localization_core_simlocal_frame.hpp, error_stats.hpp
localization_core_test_supportcheck.hpp
AccuracyOverlaygazebo gui plugin, plus sim/gui.configgazebo, qt5

The tests here only build when this is the top-level project. Add -DLOCALIZATION_CORE_BUILD_TESTS=ON to build them from a project too.

4. change shared code

A submodule is pinned to one commit, so a change here does not reach a project until you move its pointer:

  1. Edit, test and commit in ~/localization_core.
  2. In the project: git -C external/localization_core pull (or check out the commit you want).
  3. Rebuild and test the project, then git add external/localization_core && git commit.
While working on both at once you can also edit inside external/localization_core directly, since it is a full clone. Commit there, push it back to ~/localization_core, then commit the new pointer in the project.

5. the real hardware

  1. Raspberry Pi 4 UARTs. docs/uart.sh has the notes for enabling uart0 (gps) and uart4 (imu).
  2. Check the receiver. test/python/get_data/get_data.py captures raw NMEA from the serial port. test/python/get_data/data.txt is a recorded log you can replay without hardware.
  3. MTi-630. In MT Manager enable the quaternion and (preferably) free acceleration outputs at 100 Hz, and set the magnetic declination, otherwise “north” is magnetic north.

6. publish to GitHub

gh repo create localization_core --public --source ~/localization_core --push
gh repo create gnss_imu_prediction --public --source ~/gnss_imu_prediction --push
gh repo create drone_localization --public --source ~/drone_localization --push

Because the submodule URL is relative, it resolves to the sibling repository on GitHub with no change. GitHub's language bar ignores submodule contents, so each project shows only its own languages.
